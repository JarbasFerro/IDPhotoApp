**Status:** In progress

**Purpose:** Index the controlled color and context test evidence requested by [`../06-identity-exploration-handoff.md`](../06-identity-exploration-handoff.md) §7, and state the rules every piece of evidence follows.

---

## 1. What this folder is

This folder holds **evidence**, not decisions. Nothing here approves a color or a symbol. Decisions are recorded only in [`../99-brand-decisions-log.md`](../99-brand-decisions-log.md).

Two facts frame everything in this folder:

- **The icon is a draft.** `../assets/calipic-icon-draft-v0.svg` is a stand-in. The symbol territory is provisionally frozen (BD-036), but the drawing needs substantial form refinement, and the final icon is expected to gain finishing touches — shadows, depth, texture — rather than stay a flat glyph. All current renders use v0 flat.
- **The palette is a test palette.** The hex values come from BD-037 and are test values only. BD-033 is unchanged: no brand color is approved.

## 3. The re-run rule

Every render in this folder must be reproducible from a script that takes the icon as an argument:

```sh
scripts/brand/<name>.sh <icon.svg>
```

For the current round the argument is `docs/brand/assets/calipic-icon-draft-v0.svg`.

This rule exists because the icon will change. When the refined, finished icon is ready, the same scripts are run against the new file and every matrix, size sheet, accessibility simulation and product-context render is regenerated. Findings are then compared with the v0 findings rather than assumed to carry over — a flat glyph and an icon with depth and texture can behave differently at small sizes, in grayscale and in Dark Mode.

Consequences for anyone adding evidence:

- no hand-made or one-off renders; if an image cannot be regenerated by a script in `scripts/brand/`, it is an illustration, not evidence, and must be labelled as such;
- scripts read the test palette from one place and must match BD-037; do not hard-code different values per document. Values BD-037 does not define yet (Dark ink for system C, Increase Contrast variants) are added to BD-037 first;
- scripts must not modify the icon geometry. Color, background, size and context change; the mark does not;
- each document names the script and the exact command that produced its images;
- generated images live beside the document that uses them, in this folder.

`scripts/brand/` does not exist on `main` yet; it is delivered by the same separate PRs as the documents above. Until then this section is a requirement, not a description.

## 4. Evaluation rules inherited from the brand documents

- Do not choose a color from an isolated swatch; judge the full icon and real product surfaces (handoff Step 1).
- Reject anything that only works at 1024 px (handoff Step 2).
- The interface stays neutral enough that skin tones remain visually primary ([`../03-color-strategy-research.md`](../03-color-strategy-research.md) §7).
- Status colors (`pass`, `warn`, `fail`, `manual_check`) stay semantically independent of the brand accent and are never color-only (03 §5–6). Test system D shares a hue family with `warn`; testing that collision is part of the point (BD-037).
- The credit-purchase screen (03 §9 item 8) is outside handoff Step 4 and therefore outside `04-product-context.md`; it remains owed before color lock.
- Light and Dark Mode are judged as equals (BD-019).
- Avoid contemporary purple/gradient AI branding (handoff Step 1, BD-013).
- When good options conflict: native iOS familiarity, then beauty, then accessibility; correctness, privacy and truthful compliance language are not traded (BD-034).

## 5. What happens after this folder is complete

1. The founder reviews `05-color-recommendation.md`.
2. The icon drawing is refined and finished (BD-036 amendment).
3. All scripts are re-run on the refined icon and the findings are updated.
4. Only then can BD-033 (color) and BD-036 (icon) move from Working / Research in progress toward Accepted, together.
